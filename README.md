# 一袋米要扛几楼（ItamiTimer）

Windows 桌面端**带强制约束的专注任务计时器**：勾选本轮允许的几组应用，提交任务；此后只有待在这几组应用里、且人在座的时间才算专注时长。切到别处会被置顶提醒（不抢键盘焦点），那段时间不计入，任务因此被拖长。

它的计时**完全建立在 ActivityWatch 的事件历史之上**，程序自己不攒任何计时状态——所以中途关掉界面、甚至重启电脑，都不影响计时和最终结果。下次打开它会重放历史，告诉你上次那个任务是完成了、还差多少，还是该开个新的。

名字本身就是「疼痛感」的意思——治的是切走的惰性。痛感来自时间惩罚，和结束时那份诚实的账单：

```
任务：读书学习
承诺专注 25 分钟，实际耗时 41 分钟

  偷懒 5 次，共 11 分钟
      chrome.exe        8 分钟
      Weixin.exe        3 分钟
  离开              3 分钟
  AW 无数据          2 分钟（不计入）
  中途放宽限制 1 次   10:23 增加了「网页学习」
```

## 核心思路

- **状态是推导出来的，不是攒出来的。** 程序不持有"剩余多少秒"这种累加值。要知道进度，就拿任务的开始时间向 AW 查 `[开始时间, 现在]` 这段区间的全部事件，重放一遍算出来。所以关掉程序、重启、崩溃都不丢账——历史存在 AW 里，不在本程序里。副作用：轮询间隔只影响提醒的及时性，不影响核算精度。
- **判定模型**：一段时间计入专注时长 ⟺ 在做正事（活跃应用命中**当时**已勾选的活动组）**且**人在座（AW 的 afk 数据）。切走的时间不计入并触发置顶提醒；人离开的时间不计入但不提醒；AW 没数据的时间既不计入也不算偷懒，如实报告。
- **任务一旦提交就已确定。** 开始时间固定，时长锁定。休息结束就是任务终结，**绝不自动开始下一轮**——那相当于程序替用户强制加了个任务。
- **活动组**：勾选列表不是实时进程列表，而是预定义的「活动组」——每组一个易记的中文名（如 `读书学习`）配一批匹配 AW `app` 字段的正则，Windows/macOS 的同类应用收进同一组。规则文件是 `rules.json`，格式借鉴姊妹项目 [ActivityWatchJournal](../../../Python/ActivityWatchJournal) 的 `config/classify_rules.yaml`（那边攒的两百多条真实 app 名可以当字典抄）。中途可以改勾选，但只对此后的时间生效——否则就能摸鱼完再勾上、让偷懒追溯变成专注。
- **AW 是底座，不是零件。** [ActivityWatch](https://activitywatch.net/) 是一个多平台、已经做好了的工具，负责如实记录行为。这个项目的全部意义是**借这份已有的、客观的记录来约束自己**，而不是自己去实现行为监测。所有判定输入只来自它的本地 REST API（`http://127.0.0.1:5600`），不调用任何 Windows 原生窗口枚举/监听 API——唯一的平台特定代码是"置顶但不抢键盘焦点"这一小块。
- **跟 [ActivityWatchJournal](../../../Python/ActivityWatchJournal) 是兄弟，不是上下层。** 那个项目是同一个底座的另一个读者（回溯记账），这个是当下约束。两者共享**规则文件**（app 名字典），界面顶部的分类统计面板可以按需调它，但**约束和核算不经由它**——否则 Python 环境会变成核心功能的单点故障。详见 `DESIGN.md` §2.1。
- **提醒行为**：主窗口置顶显示，但**不抢键盘焦点**——纯视觉提醒，不打断你在别的 App 里正在做的操作。

完整决策记录、任务生命周期、重放算法、规则文件格式、AW 接口约定、配置项默认值见 `DESIGN.md`。

## 依赖

- [ActivityWatch](https://activitywatch.net/) 需要在本机运行——这是**唯一的硬依赖**，AW 访问不了程序就直接提示无法工作，不做任何猜测和降级。程序不会启动/管理 AW 进程。两个监听器**都必需**：
  - `aw-watcher-window`（`currentwindow` bucket）—— 判断在不在做正事
  - `aw-watcher-afk`（`afkstatus` bucket）—— 判断人在不在。**不是可选项**：AW 的窗口监听器即使人走开了也会心跳续期当前窗口那条事件，不看 afk 数据的话「把目标应用停在前台然后起身走开」是完全隐形的作弊路径（见 `DESIGN.md` §6.1.1）
- .NET 10 SDK（`net10.0-windows` target），无外部 NuGet 依赖（规则文件用内置的 `System.Text.Json`）
- Windows + Visual Studio 2026（WinForms 设计器）
- 可选：[ActivityWatchJournal](../../../Python/ActivityWatchJournal) 用于界面顶部的分类统计面板。缺了只是统计不可用，计时器照常工作（见 `DESIGN.md` §2.1）

## 构建与运行

```
dotnet build
dotnet run
```

或直接用 Visual Studio 2026 打开 `ItamiTimer.slnx` 运行/调试。

## 项目结构

- `DESIGN.md` — **架构设计文档（v3），唯一的决策来源**，改动前先对照它
- `PainForm.cs` / `PainForm.Designer.cs` — 主窗口（当前为空白脚手架）
- `Program.cs` — 入口
- `wild-enchanting-planet.md` — 已被取代的 v1 设计，仅作历史记录
- `rules.json` — 活动组规则文件（尚未创建，格式见 `DESIGN.md` §5.2）

运行时数据在 `%APPDATA%\ItamiTimer\`：`current-task.json`（当前任务记录）+ `history.jsonl`（已完成的任务）。
