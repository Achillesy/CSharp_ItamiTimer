# ItamiTimer

一款为 Windows 和 macOS 打造的、**带强制约束**的桌面专注计时器。

传统番茄钟全靠自觉；ItamiTimer 不信任你。它读取本机 [ActivityWatch](https://activitywatch.net/)
记录的真实窗口活动历史，只把你**确实**待在承诺目标里、且人在座的那些秒数算成专注。开个浏览器、
切到聊天软件，或者干脆走开——那些时间悄悄地不计入：表盘上的灰色截止弧会往前滑，你只能眼睁睁
看着它变长。

## 番茄工作法，以及这里跟它的不同

经典手法（Cirillo，1980 年代）：选一个任务，定 25 分钟，响了就停，歇 5 分钟；每四轮再歇长一点。
它的两个已知弱点：计时器量的是**流逝时间**而非**专注时间**，合规全靠自觉。

ItamiTimer 保留骨架——一次承诺、一段专注、一段挣来的休息——但把自觉换成审计：

| | 经典番茄钟 | ItamiTimer |
|---|---|---|
| 计入什么 | 墙钟时间 | 只有命中所选目标、且人在座的那些秒 |
| 计时器状态 | 内存里的倒计时 | **没有倒计时这回事**。表盘是 ActivityWatch 历史的投影 |
| 偷懒 | 计时器照跑 | 秒数不计入；截止弧往前滑——任务被拖长 |
| 离开（AFK） | 计时器照跑 | 不计入，也不算你的错——画成空心虚线框，不是红色 |
| 惩罚 | 没有 | 时间本身。什么都不作废，什么都不响，你只是完成得更晚 |
| 休息 | 固定 5 分钟 | ⌈专注分钟数 ÷ 5⌉ 分钟，从检测到达成那一刻起算 |
| 每 4 轮一次长休息 | 有 | 没有——一个任务 = 一段专注 + 一段休息，然后程序**停下来等你** |
| 自动开始下一轮 | 常见 | **绝不会**。开始任务永远是你自己的动作 |
| 报表 | 各家不同 | 屏幕上永远没有。表盘上的色块就是全部故事 |

## 窗口

2.0.0 起窗口**没有边框、没有背景**——没有标题栏，没有外框，也没有那层灰底。表盘直接
落在你的壁纸上；只有 Start 按钮以下那部分留了一张浅色卡片垫底，让滑块和目标列表还看
得清。

没了标题栏，两件日常操作跟着变：

- **拖表盘移动窗口**。表盘上任意位置都行，下面那些控件照常响应自己的操作。（拖动范围
  跟着实际画出来的东西走，所以表盘外接矩形的四个角不算在内。）
- **在表盘上点右键关闭窗口**（任务栏 / Dock 那条路照旧）。任务没结束时照样先问一句
  ——退出等于放弃这一轮，这条从来没变过。

窗口右上角有四个图标，排成 2×2：滴答、置顶、设置，以及 3.0.0 新加的**浅色 / 暗色主题**。
主题图标画的是**你现在在哪一档**，不是"点了会变成什么"：日间是太阳，夜间是一块被咬掉
一口的月亮饼干。点一下整扇窗口一起换（表盘和骨牌也跟着），选择会记住。没有"跟随系统"
这一档，两态就是全部。

3.3.0 起**跑偏时钟面会闪**——每一秒翻到相反的那一档再翻回来，黑、白、黑、白，一直闪到
你回来。参与的只有盘面、刻度、指针；木边框、色环、卡片以及其它窗口**全都保持你设定的
样子**。这是提示，不是换主题，而且跟这里其它东西一样是沉默的——不弹窗，不出声。稳定
反着的钟面看一分钟就变成壁纸了，闪的不会，这就是它的全部意义。（一秒一翻 = 0.5 Hz，
远低于光敏性癫痫的风险阈值。）它读的是程序在任务期间维护的那份"每秒一格"的
ActivityWatch 镜像，所以**不额外花任何查询**。

有一件事得先知道：ActivityWatch 要过几秒才吐出"你换窗口了"这个事实，所以两个方向都有
**3~10 秒**的延迟。以及 **ActivityWatch 挂掉时钟面保持你设定的样子**——那段时间账本本来
就按专注算，一个跟账本对着说话的提示比没有提示更糟。

窗口会记住你上次把它放在哪。万一某个位置跑到屏幕外面去了（拖过了头，或者它原来待的那
块显示器已经拔掉了），松手之后它会自己回到可见区域。**在两块显示器之间拖不受影响**：
松手时它落在哪块屏上占得多，就归位到那一块。

## 环境要求

- 本机跑着 [ActivityWatch](https://activitywatch.net/)，**两个** watcher 都要有：
  `aw-watcher-window`（在做什么）和 `aw-watcher-afk`（人在不在）。afk watcher 不是可选项——
  窗口事件靠心跳持续增长，就算人已经走开也一样，没有 afk 数据的话，"停在目标应用上起身
  走开"这种事完全隐形。
- .NET 10 运行时（编译需要 SDK）。

## 编译与运行

```bash
dotnet build ItamiTimer.slnx
dotnet test ItamiTimer.slnx
```

Windows 下发布（**必须指定 RID**，不指定的话所有平台的 Skia/HarfBuzz 原生库都会被打进去，
膨胀到约 560MB）：

```bash
dotnet publish src/ItamiTimer.App -c Release -r win-x64 --self-contained false -o "$LOCALAPPDATA/Programs/ItamiTimer"
```

结果：约 27MB，35 个文件。发布时会自动剔除两个巨型原生 `.pdb`（csproj 里的一个 MSBuild
target 做的——`dotnet publish` 本身不会剔除）。

macOS——必须打成 `.app` bundle（图标、Dock、以及 Finder 启动时需要的 `DOTNET_ROOT`
环境变量）：

```bash
./pack-macos.sh --dmg
```

Windows——要给别人用而不是本机开发调试时，打一个安装包（`dist/ItamiTimer-<版本>-win-x64.exe`）。
装机时会检测 .NET Desktop Runtime，没有就提示下载安装，目标机器不需要预装 .NET。需要
Inno Setup 6（`winget install --id JRSoftware.InnoSetup -e`）作为构建工具：

```powershell
.\pack-windows.ps1
```

专注时长滑块在 Release 版是 **10–50 分钟**，Debug 版是 **3–10 分钟**——这样开发时不用真的
坐等 25 分钟才能看到达成那一刻。

## 项目结构

```
src/ItamiTimer.Core/    net10.0  核算引擎：规则、判定 buffer、投影计算。
                                 无 UI、无平台调用——由 csproj 强制约束。
src/ItamiTimer.Cli/     net10.0  `itami`——拿真实 ActivityWatch 数据干跑引擎。
                                 唯一会打印报表的地方。
src/ItamiTimer.App/     net10.0  Avalonia 界面：表盘、骨牌、声音、闹钟、Alarms 清单、设置。
tests/                  xUnit    纯函数测试：合成事件，不需要等待。
```

程序画的每一样东西——表盘、骨牌、窗口图标、exe 图标本身——全部是计算出来的矢量几何。仓库
里不含任何位图或音频资源；连滴答声都是运行时合成的（白噪声脉冲 + 阻尼正弦），提示音直接用
操作系统自带的。

运行时数据：

| | |
|---|---|
| Windows | `%LOCALAPPDATA%\ItamiTimer\` |
| macOS | `~/Library/Application Support/ItamiTimer/` |

| 文件 | 由谁写 | 内容 |
|---|---|---|
| `rules.json` | **你**，手写 | 你的目标，以及可选的 `executeCommand` |
| `settings.json` | 程序 | 声音选项、开关状态、闹钟时间、窗口位置 |
| `during.json` | 程序 | 每个目标累计的专注秒数 |
| `alarms.cron` | **你**，手写 | 周期提醒，一份标准 crontab，见下文 |
| `layout` | **你**，手写 | 可选；写一个 `compact` 把窗口缩小，见下文 |
| `itami.log` | 程序 | 1MB 滚动；界面全程沉默，这是唯一能事后查清发生了什么的地方 |

### 把窗口缩小一点

窗口偏高——2560×1440、125% 缩放下大约占屏幕高度的 60%，其中表盘就占了一半。所以有一档
**紧凑**尺寸：表盘和骨牌缩到约四分之三，窗口宽度跟着缩。**控件和字号一个都不动**
——按钮、滑块、目标列表、右上角那四个图标都保持原样，不会变得更难看清或更难点中。

在上面那个数据目录里建一个叫 `layout` 的文件（没有扩展名），内容就一个词：

```
compact
```

写别的（`standard`、空文件、干脆没有这个文件）都是原来的尺寸。

**它只在程序启动时读一次。** 程序运行中改它不会有任何变化，要下次启动才生效。这也正是
它单独一个文件、而不是 `settings.json` 里一行的原因：那个文件程序随时会整份重写，你的
修改会被覆盖掉。

任务状态**永不落盘**。关掉程序等于放弃当前这一轮——不过已经挣到的时间仍然会被计入
`during.json`。

### 周期提醒（Alarms 清单）

跟表盘上那根手拨的一次性闹钟针不是同一回事：ItamiTimer 还盯着**一份标准 crontab**，
处理那些会反复回来的事——吃药、每晚的打卡、每月的对账。自己手写数据目录下的
`alarms.cron`：

```cron
# ItamiTimer alarms.
# 第 6 列是提醒文字，不是命令，永远不会被执行。
#
# 分   时    日  月  周     提醒文字
  0    14    *   *   *      吃药
  30   21    *   *   1-5    晚间打卡
  */30 10-18 *   *   MON-FRI  起来走两步
# 0    7     *   *   *      注释掉的这条不响
  @daily                    每日回顾
```

五个时间字段**严格照 crontab(5)**——`*`、`5`、`1-5`、`1,3,5`、`*/15`、`1-9/2`、
三字母星期和月份名、`0` 和 `7` 都是周日，以及 `@daily`/`@hourly`/`@weekly`/`@monthly`/
`@yearly` 这组别名。包括那个经典的坑：**日和周两栏都不以 `*` 开头**时它们是「或」，
所以 `0 0 1 * MON` 在每月 1 号**或**每个周一都会响。`@reboot` 不支持。

这份文件的其它规矩都很直白：

- **第 6 列是文字，不是命令。** 这份文件跑不了任何东西。
- **不做任何检查。** 解析不了的行安静跳过——不警告、不记日志。你能拿到的是反过来的
  那个信号：**每一条真响过的提醒都会往 `itami.log` 写一行**，带上命中的表达式
  （`Alarms list fired 23:55 [55 23 1 * *] 月度对账`）。提醒没来就去翻日志，查不到记录就说明
  这条规则从没命中过，也就是你写错了。
- **程序只读。** 从不回写，也不会替你建这个文件。想让某一行暂时不响，行首加 `#`。
- **不补响。** 程序关着的时候错过的提醒直接跳过，它只从启动那一刻往后看。

每分钟检查一次，到点的提醒会弹系统通知——**一条提醒一个通知，永远不合并**——外加骨牌
上的一条提示条；要不要同时出声是 Settings 里的一个开关。同一分钟撞上好几条时，提示条
只显示前两条、其余计成 `+N`，但**系统通知和日志一条都不会省**。

下一条提醒在 12 小时以内时，表盘木框内侧会出现一个小圆环：**红色 = 一条；橙色、中心带一个
红点 = 那一分钟不止一件事**。点一下圆环可以瞄一眼下一条是什么。

#### 从 3.6.x 升级

3.7.0 用上面这份 crontab 取代了原来的 Markdown 清单（`alarms.md`，一行一个绝对时间戳）。
**旧文件完全不再读取**——不迁移、也不提示。把还要用的内容自己手工搬进 `alarms.cron`；
真正一次性的事在 crontab 里没有对应写法，那种用表盘上的闹钟针。

## 干跑引擎

```bash
itami start                              # 列出 rules.json 里的目标，让你选
itami start --group 编程 --minutes 25
```

它在终端里跑一轮真实计时，用**跟界面完全相同的镜像、相同的判定代码、相同的一分钟节拍**
（DESIGN §7.5）。每分钟打一小块：时间和进度、跑偏时的一行说明、外加一张固定的 **2×60 画布**
——就是**表盘的两圈**，一列一分钟，纯 ASCII：`F`/`M`/`L` 表示 41-60 / 21-40 / 1-20 秒专注，
`#` 跑偏，`*` 离开，`-` 还欠着，`.` 程序没在跑。这是检验你的规则到底有没有匹配上实际行为
最快的办法。

它验的是**引擎，不是会话**：没有休息阶段、没有键鼠空闲提醒、没有"休息起点跟着后退"那套
投影。达成即打账单退出。全程不写盘。

## 挑选和试跑闹钟要执行的命令

rules.json 里的 `executeCommand` 是一份常用命令收藏夹，**闹钟永远只跑第一条**。
`itami commands` 就是用来换第一条、以及在不等闹钟真到点的前提下试跑某一条的：

```bash
itami commands --list          # 只看（* 标出 #0），什么都不改
itami commands --select N      # 把第 N 条挪成 #0（改写 rules.json，留一份 .bak）
itami commands --execute       # 跑 #0，y/N 确认后执行
itami commands --execute --yes # 跑 #0，不问（闹钟到点走的就是这条）
```

`itami` 跟程序装在一起——就在安装目录里，`ItamiTimer.exe` 旁边。

**不是上面这几个精确形式的，一律只打印清单、什么都不改**：不认识的开关、裸
`commands`、`--select` 不带数字、数字越界、`--execute` 带了参数……都算。**唯一会执行
东西和唯一会写文件的两条路都必须是精确形式**，所以打错一个字最多只是看到一份清单。

它操作的是**程序真正在用的那一份 rules.json**（`AppData.RulesPath` 的三级查找链），
并且把这个路径打在第一行。选完对正在运行的 ItamiTimer **立刻生效**——闹钟到点那一刻
会重读 rules.json，不用重启。

**`--execute` 刻意不带编号**：想试别的就先 `--select` 把它选成 #0。这样"你试的那条"和
"闹钟真正会跑的那条"在设计上就是同一条，不存在"我刚才测的到底是哪条"这种事。换序是
文本级搬运，绝不做 JSON 往返序列化：你写的注释和缩进逐字节保留；碰上它拿不准的数组
形状会直接拒绝改写，而不是猜。

### 闹钟到点的时候发生了什么

程序到点把命令**发出去就立刻返回**，全程不等——命令挂住也卡不到时钟。**两个平台一样**：
直接把命令跑起来，退出码、stdout、stderr 全部写进 `itami.log`，**不弹任何窗口**。

**有一类失败它看不见，你得知道**：极少数命令只把失败讲给控制台听。`shutdown /h` 在没
启用休眠的机器上退出码 0、stdout 和 stderr 都是空的、机器纹丝不动——"此系统上没有启用
休眠"那句话绕过了管道。这是一条命令的一个分支，不是普遍现象（同一条 `shutdown` 的帮助
文本、无效参数提示、找不到的命令、不存在的路径，失败信息都老实走管道，抓得到）。

**所以：命令看着没生效、日志又只有一句 `exited with 0` 时，去终端里跑一次**

```bash
itami commands --execute
```

那里有真正的控制台，那句被吞掉的话就出来了。这也是 `itami` 跟程序装在一起的原因。

**macOS 上有一点要知道**：默认那几条大多在驱动 System Events（重启、睡眠、注销、关机），
它需要「自动化」权限——系统设置 → 隐私与安全性 → 自动化。这个权限是**按 App 授予**的，
而 ItamiTimer 一开始并没有，所以这几条第一次执行时会弹一个授权框。要是当时没人在键盘前，
命令就一直等着，60 秒后日志里会出现 `still running`。点一次"允许"就好了。不碰 System
Events 的条目（`pmset`、`open`）不受影响。

你的命令仍然由 `cmd.exe /c`（Windows）/ `sh -c`（macOS）解释，跟以前**一模一样**——
`rules.json` 里的东西没有一条改变含义。变的只是它们**在哪里**跑。
